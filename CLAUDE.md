# CLAUDE.md

Guidance for Claude (Code or chat) working in this repository.

## Project

**ephora-operator** — a Kubernetes operator that provisions and automatically tears down ephemeral preview environments per Pull Request, built with **Operator SDK (Helm plugin)**.

Full context:
- `docs/dat-ephora-operator.md` — technical architecture document (components, CRD spec, reconciliation loop, security model, NFRs)
- `docs/adrs-ephora-operator.md` — architecture decision records (ADR-01 to ADR-04)

Read both before proposing structural changes — several choices below are deliberate decisions, not defaults to reconsider casually.

## Stack and non-negotiable decisions

- **Framework**: Operator SDK with the **Helm plugin** — not Kubebuilder, not the Go/Ansible plugin. The reconciliation logic wraps a Helm chart deploy, not a custom Go controller loop (ADR-01). Don't introduce a Go-based controller pattern unless the ADR is revisited first.
- **Trigger mechanism**: CI applies/deletes the `PreviewEnvironment` CRD directly via `kubectl`. No HTTP webhook/endpoint exposed by the operator (ADR-02). Don't add an API server or webhook receiver to "simplify" CI integration.
- **Network exposure**: internal access only in this version — no dynamic Ingress, no DNS/TLS automation (ADR-03). This is explicitly deferred to a later version, not an oversight.
- **Isolation model**: one dedicated namespace per environment (`preview-pr-<n>-<app>`), destroyed entirely on cleanup rather than deleting individual resources (ADR-04).

## API

Group: `ephora.io`, version `v1alpha1`, kind `PreviewEnvironment`. Canonical field list is in the DAT (`docs/dat-ephora-operator.md`, section 3) — treat that as the source of truth over any partial example in code comments or README.

Key invariants when touching the CRD or reconciler:
- `spec.prNumber` is immutable after creation.
- `spec.ttl` must remain bounded by a schema-level max (see DAT §7 risks) — never remove this validation to "simplify" testing.
- `spec.source.repo` must stay restricted to allow-listed internal Git hosts (pattern validation) — this is a security control, not a placeholder.
- A finalizer (`ephora.io/preview-cleanup`) must guarantee namespace + Helm release teardown before the CRD is removed. Don't remove or bypass it, even temporarily for debugging — use `kubectl patch` to strip it manually if needed, don't delete it from the CRD spec.

## Commands

```bash
make install    # install CRDs into the current kube context
make run         # run the operator locally against the current kube context
make test        # run unit/integration tests (envtest)
make manifests    # regenerate config/crd/bases from kubebuilder markers on api/v1alpha1 types
make generate    # regenerate api/v1alpha1/zz_generated.deepcopy.go
make build       # compile the manager binary to bin/manager
make docker-build IMG=<tag>  # build the manager image
```

Note: the project has a real Go manager (cmd/main.go, api/v1alpha1, internal/controller) rather than
the zero-code generic `helm-operator` image the Operator SDK Helm plugin scaffolds by default — see
the note at the top of cmd/main.go for why (short version: ADR-01 already anticipates this as a
fallback once the dynamic per-instance chart source, TTL, and finalizer logic exceed the plugin's
default single-static-chart reconciliation model).

## Conventions

- Namespace naming: always `preview-pr-<prNumber>-<appName>`, lowercase, generated by the reconciler — never hardcoded elsewhere.
- Every namespace created for a preview environment must get a default-deny `NetworkPolicy` and a `ResourceQuota`/`LimitRange` — this is part of the reconciliation contract, not optional hardening to add later.
- No production secrets, ever, in `spec.valuesOverride` or anywhere injected into a preview namespace.
- Metrics to preserve/extend: `preview_environments_active`, `preview_environment_provisioning_duration_seconds`, `preview_environment_cleanup_total` (DAT §6).

## When proposing changes

- A change that touches ADR-01 through ADR-04's decisions (framework choice, trigger mechanism, exposure model, isolation model) should be flagged explicitly as revisiting an ADR, not applied silently.
- New V2-scope features (public Ingress, PR comments, FinOps dashboard) belong behind a clear flag/toggle, not folded into the default V1 path (DAT §8 roadmap).
